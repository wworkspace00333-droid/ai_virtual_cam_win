# Windows-версия: аудит перед 0.5 (2026-11-16)

Предмет: существующая Windows-версия AI Virtual Camera Studio, ветка `windows-port` = `win/main` @ `bd3c8c1`,
установленная программа 0.4.1. Во время аудита код программы не менялся, коммитов и push не было. Созданы только
документы в `docs/` и временные файлы прогонов. С разрешения владельца удалены временные папки тестов (≈10 ГБ),
из-за которых закончилось место на диске.

Подробности: [матрица функций](WINDOWS_FEATURE_MATRIX.md), [технический долг](WINDOWS_TECHNICAL_DEBT.md),
[тесты и покрытие](WINDOWS_TEST_COVERAGE.md), [план 0.5](WINDOWS_ROADMAP_0.5.md).

## 1. Как проверялось

- **Машина:** Windows Server 2025 Datacenter (сборка 26100), Xeon 6975P-C 2 ядра / 4 потока, 31 ГБ, **без
  видеокарты** (Microsoft Basic Render Driver, Direct3D через WARP), вход по RDP. Python 3.12.10, ONNX Runtime
  1.24.4 (`onnxruntime-directml`: провайдеры DirectML и CPU).
- **Тесты:** полный набор с покрытием; opt-in стресс и живые тесты; самопроверка установленной программы.
- **Живые проверки:** регистрация камеры (`mf_client_test --list`, реестр через `vcam_status`), чтение камеры
  клиентами Media Foundation (Frame Server) и DirectShow, видеофайл → камера в установленной 0.4.1, захват экрана
  при подключённом RDP, попытка открыть камеру в браузере.
- **Замеры:** `scripts/benchmark.py` (20 с на режим), длительный прогон 20 мин со сбоями (`--soak`), отчёт ПК
  (`windows_pc_report --quick`) из установленной 0.4.1.
- **macOS 0.5 для сравнения:** `git fetch` репозитория `ai-virtual-camera-studio` — он заканчивается на **0.3.2**
  (теги v0.1.0–v0.3.2). Функций 0.5 (сцены, планировщик фаз 0–6, автокадрирование и т. д.) нет ни в одном доступном
  репозитории; сравнение — с описанием 0.5, а не с кодом.

Чего проверить нельзя на этой машине: видеокарту (DirectML, D3D11 на GPU, VRAM), физические веб-камеры, Zoom /
Teams / Discord / «Камеру» Windows (их нет), браузер с камерой (встроенный браузер запрещает доступ к камере).

## 4. Ответы на главные вопросы

**Есть ли настоящая собственная виртуальная камера?** Да. Две собственные реализации, без драйвера ядра:
Media Foundation Virtual Camera (Windows 11, через Frame Server) и DirectShow source filter (Windows 10/11). Обе
регистрируются установщиком, видны в системе, отдают кадры клиентам (Frame Server: 1080p30/60 — 30,0/59,9 к/с;
DirectShow-клиент — 30,5 к/с), показывают заставку «ожидание», когда программа закрыта или конвейер остановлен,
переименовываются из программы, корректно удаляются. OBS Virtual Camera — чужая камера, используется только как вход
или (по решению владельца) как промежуточное звено через OBS.

**Что реально работает (проверено здесь):** запуск, настройки, профили, трей, автозапуск (запись), диагностика;
входы — OBS Virtual Camera, плагин OBS, экран/окно, видеофайл, виртуальные MF/DirectShow-устройства; детекция YOLOX,
лица YuNet, трекинг ByteTrack, сегментация людей; зоны всех видов; замена картинкой/видео/цветом, размытие,
пикселизация; размытие и замена фона; компоновщик D3D11 (на WARP) с откатом на CPU; собственная камера в двух
вариантах; восстановление после сбоев (стресс 7/7).

**Что существует только формально или частично:** «любые предметы» (OWLv2 + SAM 2.1) — по тексту, но 7,8 с/кадр на
CPU и без запроса картинкой; замена по силуэту — без встроенной модели; CUDA — упоминается в текстах, но не
поставляется; «ИИ по требованию» — модели грузятся лениво, но детектор работает всегда, когда ИИ включён;
физические веб-камеры — код есть, проверен только на виртуальных устройствах; DirectML и GPU-компоновка — код
есть, без видеокарты не проверены.

**Что полностью отсутствует:** Scene Manager и атомарное состояние сцены, единый планировщик (фазы 0–6), изоляция
обслуживания, Auto-Framing, Lighting Enhancement, Gesture Control, Recording, Instant Replay, Plugin SDK, экраны
этих функций и «AI Resource Manager», CUDA/TensorRT, передача кадров без копий.

**Можно ли использовать в повседневной работе?** Для основного сценария — да, с оговорками: «видео (камера, OBS,
экран или файл) → скрытие лица / фон / логотип / замены → собственная камера → Zoom/OBS» работает и проверено
сквозным образом на сервере. Оговорки: установщик без подписи (предупреждение SmartScreen); скорость и поведение
на реальной видеокарте и в конкретных программах видеосвязи ещё не измерены; на слабом ПК без GPU выход ниже 60 к/с
(на сервере 52–57 к/с); одна программа на MF-камере одновременно (вторая — через DirectShow-камеру).

## 6. Критические проблемы

Блокирующих ошибок, ломающих основной сценарий, не найдено. Наиболее важное:

1. **Ничего не проверено на видеокарте** (D1) — главный риск продукта; все цифры выше — на CPU/WARP.
2. **Нет подписи кода** (D2) — SmartScreen; возможное недоверие части клиентов к неподписанному DirectShow-фильтру.
3. **Найдено в этом аудите:** утечка временных папок самопроверки/бенчмарка (D21, 5,2 ГБ), из-за неё полный диск;
   при полном диске модель ИИ не загружается из-за неудачной записи кэша (D23), а ошибки записи настроек не видны
   пользователю (D22).
4. **Невоспроизводимая сборка в CI:** FFmpeg «latest» без проверки хэша (D3).
5. **Неточные обещания:** CUDA в README и интерфейсе при сборке только с DirectML (D19).
6. **Аномалия режимов:** в «Максимальном качестве» ИИ работает реже всего — 2,5 к/с против 14,5 к/с (D26).
7. **Лица:** точность YuNet на видео не измерена; на пробе 3/3 видимых лица найдены, но 2 срабатывания на затылках
   (D25) — для скрытия безвредно, для правил «только лица» — ошибка.

Всего записей техдолга: 26 (D1–D26), из них найдены в этом аудите: D19–D26.

## 7. Сколько работы осталось и в каком порядке

Оценка — в [плане](WINDOWS_ROADMAP_0.5.md): P0 ≈ 1 неделя (+ железо и сертификат), P1 ≈ 2–3 недели, P2 ≈ 6–9
недель, P3 ≈ 3–4 недели; **до 0.5 — порядка 3–4 месяцев**. Порядок: замер на реальном ПК → исправление найденных
дефектов (D19–D23, D3) → подпись (параллельно) → ИИ по требованию и сегментация → планировщик → сцены → остальные
функции 0.5 → запись, повтор, SDK → выпуск 0.5.
